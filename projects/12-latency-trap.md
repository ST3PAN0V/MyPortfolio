# Latency Trap

**Ретроспектива ошибки проверки цены при автоматизированной покупке на маркетплейсе.**

| О проекте | Описание |
| :--- | :--- |
| **Формат** | Разбор произошедшего эпизода |
| **Направление** | Корректность платежей · Проверка условий покупки |

## Что произошло

При использовании снайперского ПО мы обнаружили расхождение между ценой объявления и итоговым списанием. Разбор показал разрыв между условиями, на основании которых принималось решение о покупке, и суммой в форме окончательного подтверждения. Некоторые сторонние боты подтверждали платёж без сравнения обновлённой суммы с ранее принятой ценой.

Эпизод включал намеренное изменение цен объявлений и реальные сделки на маркетплейсе. Этот материал описывает обнаруженную ошибку проверки и инженерные выводы из неё.

## Результат

По исходному описанию эпизода, после обсуждения в сообществе часть авторов затронутых инструментов исправила проверку цены.

## Инженерные выводы

- **Проверять окончательную сумму.** Цена объявления предварительна; перед подтверждением нужно сверять сумму в платёжной форме.
- **Сопоставлять условия покупки.** Предмет, сумма и валюта должны соответствовать условиям, одобренным пользователем.
- **Останавливать операцию при расхождении.** Изменившиеся условия требуют нового подтверждения пользователя.
- **Сохранять данные для разбора.** В журнале нужны исходная цена, подтверждённая сумма и идентификатор операции.
- **Проверять пограничные случаи.** Тесты должны учитывать изменение цены, устаревшие котировки и несовпадение валюты между выбором товара и подтверждением платежа.
